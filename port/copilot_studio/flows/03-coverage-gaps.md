# 03 — Coverage, gap rules and consistency

Trigger: complete EvidenceSnapshot or explicit agent query. Inputs SnapshotNumber, Release, optional TestLevel, latest approved DocumentBaselines, generated manifests, RulesFile. Outputs RTM rows, coverage ratios, gap/consistency/risk findings and recommended actions. No LLM in this flow.

1. List SnapshotMembers then their Artifact revisions and TraceLinks; paginate all Dataverse List rows. Filter origins to explicit/human_confirmed. Build collections `Artifacts`, `Links`, `LatestResults`; unconfirmed links never count as coverage.
2. For each sorted software requirement, incoming verifies from test_case gives tests; incoming implements from code_change/software_unit gives changes/units; outgoing allocated_to gives components. Join tests to LatestResults by case ID. Emit requirement revision, linked IDs and unique latest outcomes; preserve all absent relationships as empty arrays.
3. Count unique requirements with a verifying test and with an implementing change. Divide by total SRS, round percentages to two decimals; zero denominator gives 0.0. Hazard coverage follows hazard←mitigates control←implements verified requirement←verifies test. A case's outcome does not change whether a trace exists. Copy all results summary counts from 02.
4. Load G01–G12 and dispatch operation names. For missing_link use a typed anti-join on the declared link/direction/peer type. For match apply declared attrs/not_attrs; for outdated_verification use latest passing case date vs latest requirement-history ChangedDate. G12 checks SOUP requirement links and a recorded known-anomaly evaluation. Every finding includes rule, artifact ID, revision, source URL, title and configured action. Exact expressions/sets are in deterministic_logic.md; no AI decides a gap.
5. Read latest numeric `<doc>-vN` approved docs-repo tags as well as generated draft manifests. Legacy SAD Markdown lacks a manifest: parse only `COMP-nn: <name> owns/accepts/prioritizes/supplies` inventory, label the findings sad-v1. C01 compares component sets, C02 all cited IDs/revisions, C03 latest unique-result summary, C04 component titles. Keep scope (`draft` or tag), so planted stale baseline findings remain visible after fresh generation.
6. For risk rows copy hazard severity and traverse controls→requirements→units/components/tests. Run F01–F03 per hazard and F02 per control (a verified sibling cannot hide an unverified control). Proposed failure modes do not close the missing confirmed-mode gap.
7. Write JSON and Markdown to SharePoint run folder; rule summary counts and recommended actions are deterministic. Return a compact grouped report to the agent. Do not report compliance or eQMS approval.
