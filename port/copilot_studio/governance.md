# Environment and governance

Use a dedicated development solution/environment with synthetic evidence and a separate production environment after tenant review. Import versioned templates/prompts/rules/schemas into SharePoint; enable Dataverse auditing and maker role separation. Register source-reader and docs-writer connections separately; writer permissions are limited to kestrel-dhf-docs. The ADO connector does **not** support PAT authentication; use its supported Entra authentication (user or approved service identity), with least-privilege ADO permissions. CLI PATs stay in local .env and are never prompt inputs. [Microsoft connector authentication](https://learn.microsoft.com/en-us/connectors/visualstudioteamservices/).

DLP: group Azure DevOps, Dataverse and SharePoint as business connectors; block web search, consumer storage, email and arbitrary HTTP connectors. Where permitted, connector action controls deny source write operations and allow docs-repository writes. An HTTP-capable action can still address unintended endpoints: additionally enforce organization/project/docsRepoId allowlists in the solution boundary and server-side permissions. An approved Azure Function/custom connector is a separately reviewed exception; without it use the documented manual boundaries. Do not silently broaden DLP. [Data policies](https://learn.microsoft.com/en-us/power-platform/admin/wp-data-loss-prevention), [action controls](https://learn.microsoft.com/en-us/power-platform/admin/connector-action-control).

Use the organization's approved OpenAI-family model deployment, JSON output and temperature 0 where supported. Record deployment/provider/model/version and configured price. Turn generative web search and public grounding off. Restrict knowledge to the selected evidence snapshot and approved configuration library. Region and data-residency guarantees require the tenant administrator to verify environment, Dataverse, model and connector locations; this pack does not assert a residency guarantee. No source data leaves approved tenant boundaries. Only synthetic evidence is used for parity and external reference-provider checks.

Capability checklist before enabling unattended runs: Dataverse/premium ADO/SharePoint licenses; supported model JSON output; async infrastructure and target channel; controlled function endpoints; human baseline reviewer group; retention/auditing; concurrency/row-version ledger; budget telemetry. All remain **pending tenant verification** here. Core validation is native; follow native_validator.md for numeric checks or the explicitly blocked compensation. Source hashes may be reviewed imported inputs in Tier B/C; never claim freshly computed hash parity. See BUILD_PLAN.md for capability tiers and cut lines.
