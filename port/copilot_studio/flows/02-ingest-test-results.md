# 02 — Ingest runs/results and native defect links

Trigger: called after 01 before snapshot completion. Inputs organization/project, mapping, native ID lookup, snapshot. Outputs test_run/test_result artifacts and executes/reports_defect links. Source-reader connection; no test updates.

1. GET `<project>/_apis/test/runs?api-version=7.1`, reading `value`. Page with `$skip`/`$top`; retain completed runs and source dates, not current flow time as execution time. Parse release from `Release ([0-9]+\.[0-9]+)` in name using the deterministic normalization boundary; a missing release remains missing, never defaults to 1.1. Environment is buildConfiguration.platform; `retest` in name is the recorded retest flag.
2. Per run GET `<project>/_apis/test/Runs/<runId>/results?detailsToInclude=WorkItems&api-version=7.1`; page until exhausted. Canonical IDs `RUN-<runId>` and `RES-<runId>-<result.id padded to three digits>` follow the normalization contract. Map result.testCase.id through NativeToCanonical; reject missing test-case targets.
3. Copy outcome, completedDate, errorMessage and associatedBugs. Result/run synthetic markers are required before external drafting. Create result→run derives_from links and result→case executes links exactly as the reference contract and result→defect reports_defect only for native associatedBugs. Empty associatedBugs is a recorded absence (later G05), not an inferred defect association.
4. Build LatestResults: partition by test case, filter release and optional level, sort completed_at ascending then canonical result ID, retain last. This ensures a new single-case retest replaces that case only; never add all historical outcomes together. In Power Fx a collection implementation is `ForAll(Distinct(Results, test_case) As tc, First(SortByColumns(Filter(Results, test_case=tc.Value), "completed_at", SortOrder.Descending, "id", SortOrder.Descending)))`; set column names/types explicitly in the collection.
5. Count unique latest cases by outcome. Total = CountRows(LatestResults); passed/failed/blocked use filtered counts; not_run combines NotExecuted/NotRun. Requirement RTM may show a case on several requirements, but C03 compares unique test cases, not a sum of RTM rows.
6. Persist immutable revisions/membership, complete the joint work-item/code/test snapshot only after all endpoints succeed, and return counts and delta. A new RUN-3 and RES-3-021 must update the 1.1 summary from 39 passed/1 failed to 38/2 while keeping total 40.

Native endpoint response shapes and result-ID padding are supplied in `contracts/native_examples.json`; use canonical sample output to test normalization, not arbitrary model text. Source revisions must follow the actual adapter contract for test artifacts (revision "1" for run/result records; content_hash detects content changes).
