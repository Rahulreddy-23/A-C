# 04 — Bounded section drafting

Trigger: child flow, once per expanded section. Inputs SectionSpec, SnapshotNumber, Params, RunId, ModelConfiguration. Outputs section JSON (`markdown`, `claims`, `facts`, `cited_revisions`, `prompts`, `validation`, `status`, `sha256`). Read-only source access; generated output goes to Dataverse/SharePoint only.

1. Select the named query from query_catalog.md; follow explicit body-ID context closure. Build full canonical pack, then the provider view with human-labelled properties and no retrieved_at. IDs, revision strings, dates, coverage, lists and source numerical values are copied into facts. Human sections produce the fixed authoring placeholder and no model call. DRR identification is exclusively supplied input.
2. Load the exact prompt ID/version/hash and claims.v1 schema. Compute conservative UTF-8 token estimate, using ceil(bytes/3), plus prompt/schema overhead and 512 reserve. Budget is prompt.max_input_tokens. Synthesis uses one call: keep adverse results/defects and compact records for every facts-referenced ID, summarize other source types as counts, excerpt critical bodies through limits 512/256/128/0 characters, preserve all omission/excerpt audit metadata. Ordinary sections partition evidence while preserving ID-referenced context. Facts alone or one irreducible artifact too large yields evidence_over_budget. Do not silently truncate the canonical source record.
3. Cache lookup by provider/model/prompt ID/version/prompt hash/canonical evidence hash, including max_claims/preferred_kind. A hit returns the validated response with zero spend. On a miss obtain an atomic serialized budget reservation, including max output tokens; enforce 0.25 run, 1.50 build and 2.50 Anthropic / 4.00 OpenAI owner hard caps for actual-plus-reserved spend per provider. Price/model selection comes from configuration, never this document.
4. Serialize Compose Facts/Evidence with `string(outputs('Compose_Facts'))` and `string(outputs('Compose_Evidence'))`, bind them as text inputs facts_json/evidence_json, plus text max_claims/preferred_kind. Verify tenant text/output size limits before enabling the configured budgets. Invoke the converted prompt tool; temperature 0 where supported. Use JSON output only. Provider strict schema omits numeric-bound keywords; the local validator still checks confidence 0–1. Provider refusal, truncation, failed JSON, budget failure and oversized evidence each produce an ai_unavailable manual placeholder with a distinct reason; do not repeat a refused request.
5. Parse JSON and run the [native validator](../native_validator.md): Select string evidence IDs, Filter array/contains/intersection for citations, MatchAll for IDs/numbers in claim text, Conditions for kind/confidence, and audited downgrade/coercion. Exact known source URLs may normalize to a unique ID with an audit event; lookalikes and unknown IDs are rejected. Sourced without citation downgrades to inferred; disallowed kinds coerce to suggested. Extract numerical tokens using the canonical numeric-validation contract (remove artifact IDs, compare actual numbers to facts; no substring checking). Risk cells accept only their declared labels and reject severity/probability/RPN/residual-risk text. Retain all rejection events.
6. Render only validated claims. Mixed anomaly sections render the complete deterministic adverse-results table first, even when AI fails. Inferred/suggested claims retain confidence and review basis; sourced citations are hyperlinks. Deterministic sections cite every contributing evidence revision. Save fingerprints, source-only facts and prompt hashes. Emit no free-text provider output.
7. Settle reservation from usage or retain the upper bound on ambiguous failure. Store safe stop reason, HTTP status/type/request ID, never raw SDK errors or tokens. Return output including rejection/downgrade/coercion counts and reduction audit. Readiness treats ai_unavailable/stale/unresolved suggestions as blockers.

Core citation/kind/confidence validation is native. Numeric MatchAll/decimal parity is a day-1 probe; if unavailable, apply the explicit numeric_unverified → Suggested/readiness-blocking compensation in native_validator.md and keep all numbers in deterministic tables. SHA/canonicalization/AST/DOCX may use the optional function boundaries or verified offline inputs. Never silently omit governance or replace validators with a second prompt.

Select the Prompt model per section model_tier using model_tiers.md; persist actual tenant model ID/tier/parameters on DocumentSection and include them in the manifest/cache identity. GPT-5-family reference calls omit temperature and use low reasoning effort; reserve the total completion ceiling (visible cap plus configured reasoning allowance), not visible tokens alone. No nano model is enabled.
