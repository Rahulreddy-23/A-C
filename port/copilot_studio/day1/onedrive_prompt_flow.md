# Mode 2 — OneDrive-synced document exchange

Use this fallback **only if the HTTP trigger is DLP-blocked** and OneDrive for Business plus Run a prompt are allowed. Confirm the synced folder belongs to the BD tenant and is cleared for synthetic Kestrel data. This is an offline implementation guide; no BD folder or flow has been exercised here.

1. Create a synced folder with `requests/` and `responses/`. Configure `DHF_COPILOT_MODE=folder` and `DHF_COPILOT_EXCHANGE_DIR` to its local path in ignored `.env`. `dhf generate <doc> --provider copilotstudio` writes **one atomic request JSON per document** to `requests/<batch-request-id>.json`; its `sections` array contains only uncached section requests and each has the same eight fields as HTTP mode. The file includes `document_id` and a batch `request_id`.
2. Create a Power Automate cloud flow with OneDrive for Business **When a file is created in a folder**, pointed at `requests/`. Add **Get file content**, Parse JSON and a bounded **Apply to each** over `sections`. Deduplicate by batch request ID; the OneDrive trigger may fire more than once. Ignore `.tmp` files and reject malformed or oversized batches.
3. For each section invoke the same [generic Basic GPT prompt](generic_prompt.md), with the eight text inputs. Append one result `{request_id, claims_json, model, input_tokens, output_tokens}` or `{request_id, status:"refused"}`/`status:"failed"`. Keep original section order. The response file is `{request_id:<batch ID>, document_id:<doc>, sections:[...]}`.
4. Write the response atomically as `responses/<batch-request-id>.json` after all sections finish. The local adapter polls for this file for `DHF_COPILOT_TIMEOUT_S` (default 120 seconds). If syncing or flow execution exceeds that, choose an explicit larger bounded timeout for the rehearsal, and test the full document before the official demo. Missing/refused/malformed section replies remain reserved in the ledger and become human placeholders; successful replies reconcile measured usage and enter the normal per-section cache.
5. Compare the local estimated credits with the tenant **Monitor** tab. A duplicated cloud-flow trigger can consume credits twice even though the local batch ID is stable, so flow deduplication and Monitor inspection are required. Never claim local estimates equal tenant billing.

If HTTP and folder exchange are both unavailable, fall back to the [native Copilot Studio MVP](click_path_tier_b.md) (owner option A). Label every other local AI draft as **structural mock/personal-API development output**, outside the official AI evidence path.
