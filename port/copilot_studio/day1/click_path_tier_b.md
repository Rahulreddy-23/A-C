# Tier B click path: two governed sections, flows 01→07

**Scope:** Dataverse and Azure DevOps connector available, no approved code endpoint. Work in **Copilot Studio Citizen Development Sandbox**, original **Agent** creation path (or new experience → Other ways to build → Agent, Standard). This is a build procedure, not evidence that the tenant supports each action. Use [BUILD_PLAN.md](../BUILD_PLAN.md) gates before enabling a step. Synthetic Kestrel only. Flow actions below are **Power Automate cloud flows**, not agent flows looping over work items.

1. **Create the solution and storage.** In Power Apps → Solutions → New solution, choose `DHF Kestrel MVP` with a `dhf` publisher. Create `Artifact`, `TraceLink`, `DocumentSection` and `GenerationRun` using [mvp_columns.csv](mvp_columns.csv); add its alternate keys and auditing. In SharePoint, create a governed versioned library with `config/`, `runs/`, and `drafts/`. Upload exact `specs/` inputs and record SHA256. Assign separate ADO source-reader and docs-repo writer connections; verify the latter cannot write the device repo. Select an approved Basic GPT Prompt model and test JSON output, text size and the [validator cards](validator_powerfx.md) before unattended runs.
2. **Flow 01 — ingest work items.** Power Automate → solution → New → Automation → cloud flow. Add a scheduled/manual trigger, then Azure DevOps **Send an HTTP request to Azure DevOps** for read-only WIQL, workitemsbatch and revision GETs. Use Parse JSON, Select and Apply to each with bounded paging; transform native fields/tags/relations as [flow 01](../flows/01-ingest-work-items.md) specifies. Upsert immutable Artifact revisions and confirmed TraceLink rows into a new `building` snapshot; the coordinator marks it complete only after flow 02 and all counts/endpoints validate. Do not use `DHF-META` as a source of facts. Test SRS-021 revision and the source-write 403 boundary.
3. **Flow 02 — ingest test evidence.** Add a child cloud flow that reads native ADO runs/results and associated defects via connector HTTP GETs. Parse run/result IDs, outcomes and completion times, then upsert immutable Artifact and TraceLink rows in the same building snapshot. Select latest result by completion time with deterministic tie break, as [flow 02](../flows/02-ingest-test-results.md) defines. Check TC-021's latest result and defect link without model judgement.
4. **Flow 03 — compute coverage and gaps.** Add a child cloud flow over a complete snapshot. Use Dataverse List rows with indexed filters, Select/Filter array and Compose to compute the four MVP rules G01/G05/G07/G11, with stable artifact IDs and source revisions. Save the exact findings JSON and counts to the run folder. Compare the synthetic answer-key IDs in [flow 03](../flows/03-coverage-gaps.md); never ask a prompt to invent a link or count.
5. **Flow 04 — generate two sections.** Add a child cloud flow that builds deterministic facts and bounded evidence for one SSTR anomaly and one SAD component section. Use the four Text inputs in [the SSTR prompt](sstr_anomaly_prompt.md) and [SAD prompt](sad_component_prompt.md), set **fixed JSON output**, then Parse JSON with claims.v1. Run [Power Fx validator cards](validator_powerfx.md) and the native flow conditions; reject unknown citations/IDs/numbers and out-of-range confidence. Save accepted claims plus all events to DocumentSection. A refused/malformed result becomes `ai_unavailable` with a human placeholder. Do not render raw model text.
6. **Flow 05 — assemble a draft.** Add a child cloud flow that orders deterministic and validated sections by ordinal, renders Markdown and a provenance manifest into SharePoint `drafts/<runId>/`, and records content hashes/revisions. Keep failed-result tables even if the prompt fails. Mark suggestions/manual fields unresolved; no approval is implied. Use [flow 05](../flows/05-assemble-document.md) for exact contract.
7. **Flow 06 — open docs review.** Add a child cloud flow using the docs-writer ADO connection only. Create a branch/commit/PR **only in the docs repo**, add required reviewers, and post the readiness status; do not merge or approve. If ADO docs write is DLP-blocked, retain the draft in versioned SharePoint with named human review and label PR parity pending. Verify the source repo write is denied. See [flow 06](../flows/06-open-docs-pr.md).
8. **Flow 07 — change impact.** Add a scheduled poll plus allowed ADO update trigger, with a complete before/after snapshot. Diff revisions, link changes and source facts; mark SRS-021-dependent sections stale. Upload the synthetic `change_1` scenario through the authorized test path, then check exact affected section IDs before selective regeneration. If using a reviewed snapshot import, upload its post-change version instead and label live ADO integration pending. See [flow 07](../flows/07-impact.md).
9. **Connect the thin agent.** Agent → Topics → create “Draft the release test report”; ask only for release/request ID, call StartGeneration once, return the queued ID, then use GetRunStatus on a follow-up turn. Test in the pane. Publish only after source boundary, validator and readiness checks pass; after any edit, republish. Share to a Teams channel with no more than five named individuals and no group grants. Record observed tenant results in `parity_tests.md` and current credits in Monitor; until then all capability and parity statuses are pending.
