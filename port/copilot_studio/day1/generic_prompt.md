# Generic BD-approved section drafter — offline setup

Create **one** AI Builder prompt named `DHF section drafter` in the BD Citizen Development Sandbox. Select an approved **Basic-tier GPT** model shown in the tenant. Its exact versioned instructions are [copilot.generic_drafter@1](../../../specs/prompts/copilot.generic_drafter.md); paste the body after front matter without editing. The flow passes eight **Text** inputs: `request_id`, `prompt_id`, `prompt_version`, `instructions`, `facts_json`, `evidence_json`, `output_schema_json`, and `max_claims`. The latter is text in the prompt builder but a JSON integer in the adapter request.

The `instructions` field is the complete body of a versioned section prompt, such as `sstr.anomaly_assessment@3`; no Python prompt text is reconstructed in the tenant. Set **fixed JSON output** to the claims.v1 shape. The flow serializes the object to `claims_json` and echoes `request_id`. It must return the **actual tenant model name** and measured `input_tokens`/`output_tokens`; if these are not exposed, treat the adapter integration as unverified rather than inventing usage. The local credit ledger estimates before each call and reconciles the reported usage, while the tenant Monitor tab is the authoritative billing check.

The [sample request](samples/copilot_request.json) and [sample response](samples/copilot_response.json) show the exact transport envelope. The response's `EXAMPLE-...` model name and zero usage values are **illustrative placeholders**, never tenant measurements. Use `dhf copilot-request sstr anomaly_assessment --db out/evidence.sqlite` after synthetic ingest to print an exact current payload for the owner to paste into the prompt builder. It only previews; it neither posts nor reserves credits. Run the response through the reference validator before treating any claim as accepted. All sample content is synthetic; no tenant execution is claimed.
