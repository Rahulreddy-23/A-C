# Mode 1 — HTTP-triggered approved prompt flow

**Capability gate:** in the BD Citizen Development Sandbox, confirm that the **When an HTTP request is received** trigger, AI Builder **Run a prompt** action, approved Basic GPT model and Response action are allowed together by DLP. This is a click path, not a claim that the flow exists or ran.

1. In Power Automate, create a cloud flow in the DHF solution using **When an HTTP request is received**. Paste the [sample request](samples/copilot_request.json) as its JSON schema example. Limit invocation to the configured owner/service connection and tenant policy; copy the signed trigger URL only into ignored `.env` as `DHF_COPILOT_FLOW_URL`. Never paste the URL into source control, console output or screenshots.
2. Add **Parse JSON** for the trigger body. Require `request_id`, `prompt_id`, `prompt_version`, `instructions`, `facts_json`, `evidence_json`, `output_schema_json`, and `max_claims`. Reject missing or oversized inputs; accept only the reviewed synthetic dataset for this hackathon build.
3. Add **Run a prompt**, select the [generic drafter](generic_prompt.md), choose the tenant-approved **Basic GPT** model, and bind the eight text inputs. Use fixed JSON output. Keep all prompt text in the versioned `specs/prompts/` files passed by the adapter, not copied into extra flow branches.
4. Add **Response** with JSON `{request_id, claims_json, model, input_tokens, output_tokens}`. `claims_json` is the serialized fixed JSON result, never an unvalidated Markdown draft. Echo the incoming `request_id`; return the actual tenant model. Return integer `input_tokens`/`output_tokens` only if the action exposes measured usage; otherwise omit those fields and configure `DHF_COPILOT_USAGE=estimated` in ignored `.env`. On refusal or action failure, return `{request_id, status:"refused"}` or `status:"failed"` without a claims body. The default `DHF_COPILOT_USAGE=reported` rejects missing counts. In `estimated` mode, the adapter prefers valid reported counts, but missing/null usage triggers a local UTF-8 bytes ÷ 3 estimate (rounded up) for the eight prompt text inputs and serialized `claims_json`. Supplied malformed counts remain errors. Ledger, cache and document manifests preserve `usage_source: reported|estimated` (or `mixed` for aggregates); metrics label all locally calculated credits as **estimated credits**. Never fabricate usage fields or reuse the sample's zero placeholders. Tenant **Monitor** remains authoritative for billing.
5. In the reference repo set `DHF_COPILOT_MODE=http` and the signed URL in `.env`. Run `dhf copilot-request` first, then one synthetic section through `dhf generate ... --provider copilotstudio`. Inspect manifest provider/model/tier, local ledger, tenant Monitor usage, and a human placeholder for any refused output before running the full demo.

The local adapter uses a 120-second timeout by default. If the tenant cannot complete within its synchronous response window, use the [OneDrive document batch](onedrive_prompt_flow.md); do not silently accept a background response after the command times out. No tenant run has been performed by this repo.
