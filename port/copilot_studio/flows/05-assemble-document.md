# 05 — Assemble document and manifest

Trigger: all section jobs complete or explicit regenerate job. Inputs document spec, Params, ordered sections, source snapshot, prior edited Markdown/approved baseline, RunContext. Outputs md/docx/manifest, source diagrams and hashes in the run's SharePoint folder.

1. Validate required params and unique section IDs. Expand consecutive same-repeat spec entries as a group per sorted source entity. IDs are `<section>.<artifactID>`; one H2 entity heading with H3 subsections. Keep spec order and stable group IDs. All code components/units must appear; do not let the model pick them.
2. Deterministic tables use configured columns, linked source IDs and visible short Git revisions (full values stay in the manifest). Data structures have Name/Kind-bases/Fields columns. Risk severity and controls remain source tables; suggested analysis cells carry labels/citations/confidence. The diagram builder uses explicit allocation and extracted import-call edges only. Write local source and checksummed PNG when the approved renderer is available.
3. Assemble exact section bytes with stable boundary comments. Regeneration reuses actual edited Markdown between matching boundaries, including human edits; it never re-runs unaffected prompts. Reject missing/duplicate boundaries. Removed/new entities are explicit changes, not silent text loss.
4. Manifest records document/version/time/generator, spec/hash, prompts/hash, model, cost, all source IDs/native IDs/revisions/content hashes, section query/fingerprint/cited revisions/claim mix, validation and review status. Document hash covers the exact final Markdown bytes. Hash each artifact and diagram; no claims of approval.
5. DOCX renderer contract: source Markdown + baseline + timestamp → document bytes, tracked insertion/deletion/comment counts and SHA256. Table diffs are keyed by source first-column ID and operate per cell; paragraphs compare visible text. Link-target-only changes produce no visible redline. Cited links retain source revision in the label. Review comments are for inferred/suggested/manual items only. Fallback is manual Word Compare plus PR Markdown diff; label generated tracked changes unavailable until verified, not implemented by an AI prompt.
6. Store files and section records, then call readiness. Human authoring markers require reviewer and rationale; suggestion dispositions are per claim key. Unresolved markers, rejected validation without review, missing sections and stale evidence fail. Publish may open a blocked review PR; it cannot imply acceptance.
7. Return run ID, draft URLs, counts and readiness state. Add the regulatory evidence-index appendix and audit bundle only when their deterministic templates and checksum validator are configured; human compliance assessment remains separate.
