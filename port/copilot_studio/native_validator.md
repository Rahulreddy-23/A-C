# Native MVP claim validator

Run this after Parse JSON and before rendering. It is a deterministic child flow plus a Power Fx extraction step in a topic or supported Dataverse low-code plug-in. No Azure Function or second model is required for the core checks. Test the syntax and size/locale limits in the actual tenant on day 1; this file is a build recipe, not an executed tenant result.

Inputs: accepted-kind string array, evidence JSON, facts JSON, claims JSON, max_claims. Evidence IDs are a **string array**, built with Select in text mode (`item()?['id']`), not an array of objects. Keep a Rejected/Downgraded/Coerced array with claim index and reason.

1. Parse JSON with claims.v1, disallow unexpected properties and reject invalid `kind`. Local confidence check: inferred/suggested must have a value, and any supplied value must be between 0 and 1. Sourced may have null. Use Condition actions; do not depend on the provider enforcing numeric schema keywords.
2. Use `MatchAll(ClaimText, "\b(?:(?:UN|SYS|SRS|HAZ|RC|COMP|TC|BUG|PR|RUN|RES|ACT|REV|ADR|SOUP)-\d[\w.\-]*|UNIT-[a-z_]+)\b")` to produce FullMatch IDs in text. Strip a trailing period from matched IDs. Return this array to the flow. Combine citations and TextIDs with `union()`; unknowns are Filter array where `not(contains(variables('EvidenceIDs'), item()))`. Nonempty → reject `unknown_ids`. Exact source URL normalization is optional in the MVP: require ID citations and reject URL citations rather than approximate-match them.
3. Numeric extraction operates on claim text **after removing known matched artifact-ID spans**, and on the leaf values of facts (excluding booleans/null). Use MatchAll with the reference constant numeric pattern `(?<![A-Za-z0-9_])[\-+]?\d+(?:\.\d+)?(?![A-Za-z0-9_])`. Return normalized decimal values as invariant text; `Value(FullMatch, "en-US")` and configured decimal precision must pass the parity cases. Numeric tokens outside facts → reject `numbers_match_facts`. Flatten facts into a JSON array of leaf strings in the query flow, not by asking a model. ID removal can be done by ForAll matched values / Substitute over a separate working text; keep original claim text unchanged for rendering.
4. Sourced with an empty citations array → inferred, confidence defaults to 0.5 only for this downgrade; record event. Disallowed valid kind → suggested, default confidence 0.5 only for coercion; record event. Claims already inferred/suggested with missing confidence were rejected in step 1. Retain citation/confidence after coercion.
5. Risk cells require a declared cell label; reject severity/probability/RPN/residual-risk text natively with IsMatch, case insensitive. Apply the per-section max_claims after filtering and record excess claims as rejected. Rendering receives only accepted typed claims. A malformed response/refusal leaves the manual placeholder; the deterministic adverse-results table still renders.
6. Readiness checks unresolved suggestion labels and dispositions, human placeholders, unreviewed validation events and stale evidence. A successful native validation is a draft-quality gate, never approval.

Numeric compensation if MatchAll/decimal normalization is unavailable: keep citation/kind/confidence validation native. Check for digits **after known artifact-ID removal** using the available native string/character scan. Any such AI claim is forced to Suggested with confidence (default 0.5 if absent), labelled `numeric_unverified`, and blocked until a human reviews it. Configure the MVP prompt to avoid numerical prose; render numerical facts only in deterministic tables. If ID/digit scanning itself is unavailable, force **all** AI claims to Suggested and flag numeric verification pending. This is a recorded compensating control, not full numeric parity. The full reference still rejects mismatched numbers.

Native expressions use exact array membership (`contains` on an array), never substring matching. Equivalent equality of citation arrays and `intersection(Citations,EvidenceIDs)` may check containment only after deduplicating; Filter array is clearer. Persist every event and test unknown citations, IDs embedded in text, negative/out-of-bound confidence, 39 versus 40, 39.0 versus 39, and SRS-021 not being mistaken for a number.

[MatchAll reference](https://learn.microsoft.com/en-us/power-platform/power-fx/reference/function-ismatch), [prompt JSON output](https://learn.microsoft.com/en-us/microsoft-copilot-studio/process-responses-json-output), [flow expressions](https://learn.microsoft.com/en-us/power-automate/expression-cookbook).

Power Fx character-class hyphens must be escaped; use the tenant-tested pattern here, not a direct Python-regex paste. See [Power Fx regular-expression dialect](https://learn.microsoft.com/en-us/power-platform/power-fx/regular-expressions).
